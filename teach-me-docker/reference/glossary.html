Глоссарий Docker

Справочник. Дополняется с каждым уроком.

ТерминЗначениеУрок
DockerОткрытая платформа для разработки, доставки и запуска приложений.1
Образ (image)Неизменяемый стандартизованный пакет со всем, что нужно для запуска: рантайм, код, зависимости. Состоит из слоёв.1
Контейнер (container)Запускаемый экземпляр образа; изолированный процесс со всеми нужными ему файлами.1
Слой (layer)Набор изменений файловой системы: добавление, удаление или изменение файлов.1
Демон (dockerd)Фоновая служба, управляющая образами, контейнерами, сетями и томами.1
Клиент (docker)Команда в терминале; отправляет запросы демону.1
Реестр (registry)Хранилище образов. Docker Hub — публичный реестр по умолчанию.1
DockerfileТекстовый документ с инструкциями для сборки образа.2
Базовый образОбраз, который расширяет сборка; задаётся инструкцией FROM.2
Контекст сборкиПуть (обычно точка в конце docker build), где сборщик ищет Dockerfile и нужные файлы.2
Тег (tag)Читаемый идентификатор версии образа; по умолчанию latest. Полное имя: [HOST[:PORT]/]PATH[:TAG].2
Кэш сборкиКаждая инструкция Dockerfile даёт слой; изменённый слой и все после него пересобираются.2
Docker ComposeИнструмент для описания и запуска многоконтейнерных приложений одним YAML-файлом.3
Сервис (Compose)Компонент приложения; запускается из одного образа с одной конфигурацией, один или несколько раз.3
Том (volume)Хранилище, сохраняющее данные после удаления контейнера; имеет свой жизненный цикл.3
Проект (Compose)Одно развёртывание приложения; группирует и изолирует ресурсы.3
Многоэтапная сборкаНесколько FROM в одном Dockerfile; артефакты выборочно копируются между этапами, инструменты сборки не попадают в итоговый образ.4
HealthcheckПроверка, по которой определяется, «здоров» ли контейнер сервиса.4
extendsКлюч Compose: берёт сервис из другого файла как основу и позволяет дополнять или менять его настройки.4

Ключи compose.yaml

КлючЧто делает
imageГотовый образ для сервиса
buildСобрать образ из исходников
portsПорты хост:контейнер
environmentПеременные окружения в контейнере
depends_onПорядок запуска и остановки сервисов
volumesМонтирование тома: ТОМ:ПУТЬ_В_КОНТЕЙНЕРЕ
healthcheckКоманда проверки здоровья (test, interval, timeout, retries)
depends_on + conditionservice_started, service_healthy, service_completed_successfully
extendsВзять сервис из другого файла (file, service)
ports: 127.0.0.1:8080:8080Порт доступен только с самого хоста; без IP открывается на всех интерфейсах

Инструкции Dockerfile

ИнструкцияЧто делает
FROMБазовый образ
WORKDIRРабочая директория в образе
COPYКопирует файлы с хоста в образ
RUNКоманда во время сборки (результат остаётся в образе)
ENVПеременная окружения для контейнера
EXPOSEПорт, который образ хочет открыть
USERПользователь по умолчанию для последующих инструкций
CMDКоманда по умолчанию при запуске контейнера
FROM ... AS nameИменованный этап сборки
COPY --from=nameКопировать файлы из этапа, образа или именованного контекста, а не из контекста сборки

Команды

КомандаЧто делает
docker imagesСписок образов
docker psСписок работающих контейнеров
docker run -d -p 8080:80 <образ>Создать и запустить контейнер в фоне, порт 8080 хоста → порт 80 контейнера
docker stop <ID|имя>Остановить контейнер
docker build -t <имя> .Собрать образ из Dockerfile в текущей папке и дать ему имя
docker image lsСписок образов (то же, что docker images)
docker ps -aВсе контейнеры, включая остановленные
docker compose up -d --buildСобрать при необходимости и запустить все сервисы в фоне
docker compose downУдалить контейнеры и сеть проекта, тома сохраняются
docker compose down --volumesТо же и удалить тома
docker compose psКонтейнеры проекта
docker volume lsСписок томов
docker compose -f app.yml configПоказать итоговую конфигурацию (с учётом extends) для указанного файла
