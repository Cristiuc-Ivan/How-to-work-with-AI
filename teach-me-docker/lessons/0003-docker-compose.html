Docker Compose: несколько контейнеров одним файлом

Урок 3 из курса «Docker: читать чужие проекты и CI». Около 15 минут. Предыдущий: читаем Dockerfile.

Цель урока: открыть чужой compose.yaml и сказать, какие сервисы поднимутся, что с чем соединено и где хранятся данные.

Зачем это нужно

Реальное приложение — это обычно несколько контейнеров: само приложение, база данных, что-то ещё. Запускать каждый вручную через docker run, следить за сетью и уборкой неудобно. Compose позволяет описать все контейнеры и их настройки в одном YAML-файле.[1]

Связь с прошлым уроком: Dockerfile содержит инструкции для сборки образа, а Compose-файл описывает ваши запускаемые контейнеры.[1]

Из чего состоит модель Compose

ПонятиеЧто это
Сервис (service)Вычислительный компонент приложения; запускается из одного образа с одной конфигурацией, один или несколько раз[2]
Сеть (network)Через неё сервисы общаются друг с другом[2]
Том (volume)Хранилище постоянных данных сервисов[2]
Проект (project)Одно развёртывание приложения; группирует ресурсы и изолирует их от других развёртываний[2]

Каждый сервис указывает свой образ, порты, тома, сети и другие настройки.[1] Это те же понятия, что в docker run, только записанные в файл.

Читаем compose.yaml

Пример ниже я составил сам из фрагментов документации, чтобы показать типичную форму. Это не копия одной страницы, и имя переменной DB_HOST здесь условное.
services:
  app:
    build: .
    ports:
      - "8080:8080"
    environment:
      DB_HOST: db
    depends_on:
      - db

  db:
    image: postgres:18
    environment:
      POSTGRES_PASSWORD: secret
    volumes:
      - postgres_data:/var/lib/postgresql

volumes:
  postgres_data:

Читайте по ключам:

  • services — два сервиса: app и db.
  • build: . — образ сервиса app собирается из исходников (из Dockerfile в этой папке), а не скачивается.[3]
  • image: postgres:18 — образ db берётся готовый.[3]
  • ports — соответствие портов хоста и контейнера, как -p в docker run.[3]
  • environment — переменные окружения в контейнере. Образу PostgreSQL обязательно нужен POSTGRES_PASSWORD, он не может быть пустым.[4]
  • depends_on — порядок запуска и остановки сервисов.[3]
  • volumes у db — монтирует том postgres_data по пути /var/lib/postgresql (формат ТОМ:ПУТЬ_В_КОНТЕЙНЕРЕ).[3] Верхнеуровневый volumes: объявляет сам том.

Зачем том для базы

Изменения файлов в контейнере живут только пока жив контейнер: при его удалении они удаляются тоже, и база могла бы стартовать пустой.[5] Том хранит данные независимо от контейнера, у него свой жизненный цикл.[5] Поэтому в Compose-файлах с базами почти всегда есть volumes. Это отвечает на вопрос из начала: «где живут данные».

Команды

КомандаЧто делает
docker compose up -d --buildСобирает, если нужно, и запускает все сервисы в фоне; создаёт сеть, том и контейнеры[1]
docker compose downОстанавливает и удаляет контейнеры и сеть; тома по умолчанию сохраняются[1]
docker compose down --volumesТо же, но удаляет и тома[1]
docker compose psСписок контейнеров проекта (имена вида проект-сервис-1)[2]

Попробуйте в терминале

Если ещё работают контейнеры из урока 1, остановите их (docker ps, docker stop): порт 8080 нужен снова. Создайте пустую папку, в ней файл compose.yaml. Это официальный пример PostgreSQL с веб-интерфейсом Adminer,[4] в который я добавил том. Синтаксис файла я проверил командой docker compose config, но сам проект не запускал.

services:
  db:
    image: postgres
    restart: always
    environment:
      POSTGRES_PASSWORD: example
    volumes:
      - pgdata:/var/lib/postgresql

  adminer:
    image: adminer
    restart: always
    ports:
      - 8080:8080
    depends_on:
      - db

volumes:
  pgdata:
docker compose up -d
docker compose ps                  # два контейнера проекта
docker compose down                # контейнеры и сеть удалены, том остался
docker volume ls                   # том pgdata всё ещё здесь
docker compose down --volumes      # теперь удалится и том

Между up и down откройте http://localhost:8080 — это Adminer. Обратите внимание на вывод docker compose up: он создаёт сеть, том и контейнеры, как описано выше. Какие имена получили контейнеры в docker compose ps?

Проверьте себя

1. Что описывает файл compose.yaml?

Compose-файл описывает запускаемые контейнеры. Рецепт сборки образа — это Dockerfile.

2. Вы выполнили docker compose down. Что с данными PostgreSQL в именованном томе?

Тома по умолчанию сохраняются при down. Удалить их можно флагом --volumes. Образ при этом никогда не меняется.

3. Какая команда останавливает и удаляет контейнеры и сеть, но оставляет тома?

up запускает, ps только показывает контейнеры, а down убирает контейнеры и сеть.

4. Что делает ключ build у сервиса?

build задаёт сборку образа из исходников. Готовый образ берут через image, а порядок запуска задаёт depends_on.
