Образ и контейнер

Урок 1 из курса «Docker: читать чужие проекты и CI». Около 10 минут.

Цель урока: после него вы отличаете образ от контейнера и можете выбрать команду для каждого. Это основа для чтения любого Dockerfile, docker-compose и шага CI.

Что такое Docker

Docker — открытая платформа для разработки, доставки и запуска приложений.[1] Приложение упаковывается вместе с зависимостями, поэтому ведёт себя одинаково на разных машинах.

Устроен Docker по схеме клиент–сервер.[1]

  • Клиент (docker) — то, что вы запускаете в терминале. Он отправляет команды демону.
  • Демон (dockerd) — фоновая служба, которая реально управляет образами и контейнерами.
  • Реестр — хранилище образов. Публичный реестр по умолчанию — Docker Hub.

Docker Desktop, который у вас установлен, запускает демон за вас.

Две главные сущности

Образ (image)

Стандартизованный пакет: всё, что нужно для запуска (рантайм, код, зависимости). Неизменяемый: можно только создать новый образ или добавить слой поверх.[2]

Контейнер (container)

Запускаемый экземпляр образа.[1] По сути — изолированный процесс со всеми файлами, нужными ему для работы.[3]

Образ описывает, что запускать. Контейнер — это запущенное (или остановленное) воплощение этого описания. Образ лежит на диске и сам ничего не делает.

Аналогия для Java-разработчика. Образ похож на класс, контейнер — на объект: из одного класса можно создать много объектов. Аналогия неполная: образ состоит из слоёв (каждый слой — набор изменений файловой системы[2]), а контейнер — это целый изолированный процесс, а не просто область памяти.

Чем контейнер отличается от виртуальной машины

VM запускает полноценную ОС со своим ядром. Контейнеры используют общее ядро, поэтому на той же инфраструктуре помещается больше приложений.[3]

Попробуйте в терминале

Команды из официальной практики.[3] Выполняйте по порядку и смотрите на вывод.

docker images                                   # образов пока может не быть
docker run -d -p 8080:80 docker/welcome-to-docker
docker images                                   # появился образ (скачан из Docker Hub)
docker ps                                       # и работающий контейнер

Откройте http://localhost:8080. Теперь запустите второй контейнер из того же образа на другом порту:

docker run -d -p 8081:80 docker/welcome-to-docker
docker ps                                       # два контейнера
docker images                                   # образ всё ещё один

Это и есть разница: один образ, два контейнера. Уберите за собой:

docker stop <ID или имя из docker ps>            # для каждого контейнера

Флаги: -d запускает в фоне, -p 8080:80 связывает порт 8080 хоста с портом 80 контейнера.

Проверьте себя

1. Что такое образ (image)?

Образ — неизменяемый пакет. Работающий изолированный процесс — это контейнер, а фоновая служба — демон dockerd.

2. Вы дважды выполнили docker run с одним и тем же образом. Что получилось?

Образ один и не меняется, а каждый запуск создаёт отдельный контейнер.

3. Что будет с данными внутри контейнера после его удаления?

Данные, не сохранённые в постоянное хранилище, теряются при удалении контейнера. Образ при этом не меняется, он неизменяем.

4. Какая команда покажет скачанные образы, а не контейнеры?

docker images перечисляет образы. docker ps показывает контейнеры, а docker stop останавливает контейнер.
