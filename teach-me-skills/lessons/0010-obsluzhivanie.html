Обслуживание: triage, retro, architecture, setup

Цель: знать четыре скилла, которые не строят фичу, а поддерживают процесс и кодовую базу, и понимать, когда каждый нужен. Девять минут.

/setup-matt-pocock-skills: один раз на репозиторий

Это предусловие для инженерных скиллов (SKILL.md). Он спрашивает по очереди:

  • A. Трекер: GitHub, GitLab, локальный markdown (.scratch/) или другой.
  • B. Метки triage: оставить пять стандартных или переименовать. Вопрос задаётся только если установлен triage.
  • C. Документы предметной области: по умолчанию один GLOSSARY.md и docs/adr/; несколько контекстов только для настоящего монорепо.

Он пишет блок ## Agent skills в CLAUDE.md или AGENTS.md и файлы в docs/agents/. Перед записью показывает черновик, и вы можете править. Повторный запуск нужен, только если меняете трекер.

Учтите свои правила: ваш CLAUDE.md выносит spec, тикеты и конфиг трекера за пределы репозитория, а скилл по умолчанию пишет docs/agents/ внутрь. Решите, куда его направить, прежде чем подтверждать запись.

/triage: чужие сырые issues

Двигает issues и внешние PR по конечному автомату ролей (triage/SKILL.md). Применять только к тому, что вы не создавали: тикеты из /to-tickets уже готовы для агента.

Роли категории (одна)Роли состояния (одна)
bug — что-то сломано
enhancement — новая возможность		needs-triage, needs-info, ready-for-agent, ready-for-human, wontfix

Порядок работы с issue: собрать контекст и проверить, не реализовано ли уже и не отклоняли ли похожее раньше (.out-of-scope/) → порекомендовать роль → проверить утверждение (воспроизвести баг, прогнать PR) → при необходимости /grilling и /domain-modeling → применить итог. Для ready-for-agent пишется agent brief. Каждый комментарий начинается с пометки, что он создан ИИ.

/retro: улучшаем среду агента

После сессии скилл предлагает изменения не кода, а среды, по убыванию серьёзности (retro/SKILL.md). Категории: навигация, автоматические проверки, стандарты кодирования, глобальный AGENTS.md, стоимость инструментов, холостые инструкции, доступ к информации.

Механическое или суждение?Механическое нарушение (запрещённый API, форма импорта, расположение файла) закрывается детерминированной проверкой: правило линтера, pre-commit hook или шаг CI. В CODING_STANDARDS.md попадают только суждения, которые никакая проверка не заменит.

Почему стандарты проверяет ревью, а не реализация: у агента реализации самое большое давление на контекст (разведка, код, отладка), у ревьюера самое малое (ему дают diff). Это то же разделение «сделать, чтобы работало» и «сделать хорошо» из вашего CLAUDE.md.

/improve-codebase-architecture: поиск углублений

Запускается, когда есть свободная минута, чтобы кодовая база оставалась удобной для агентов (SKILL.md). Он ищет возможности углубить неглубокие модули: интерфейс почти такой же сложный, как реализация. Сначала смотрит места недавних частых изменений. Результат — HTML-отчёт во временной папке (не в репозиторий) с карточкой на кандидата: файлы, проблема, решение, выгода, диаграмма «до/после», оценка (Strong, Worth exploring, Speculative). Интерфейсы пока не предлагает. Вы выбираете кандидата, и начинается опрос по нему. Из README: это обзор, а не спасение; на старой кодовой базе он найдёт реальные кандидаты, но «ком грязи» сам не распутает.
