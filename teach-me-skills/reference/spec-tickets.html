Spec и тикеты

Источники: to-spec, to-tickets.

Шаблон spec

  1. Problem Statement
  2. Solution
  3. User Stories (длинный список «As a…, I want…, so that…»)
  4. Implementation Decisions (без путей и кода)
  5. Testing Decisions (швы, что тестировать, прецеденты)
  6. Out of Scope
  7. Further Notes

Правила среза

  • Узкий, но полный путь через все слои.
  • Проверяем или показываем сам по себе.
  • Влезает в одно свежее окно контекста.
  • Prefactoring идёт первым.
  • У каждого тикета свои blocking edges; без блокеров — можно начинать сразу.
